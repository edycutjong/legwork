# Friction log — what Arc did that the docs did not say, as it happened

Build days 1–3 (all on 2026-09-18), against `https://rpc.mainnet.arc.io` (chain 5042) and `https://explorer.arc.io`.

| # | What | Measured | Consequence in this repo |
|---|---|---|---|
| 1 | Anonymous RPC + CORS | `OPTIONS` and `POST` with `Origin: https://edycutjong.github.io` both answer with `access-control-allow-origin` echoing the origin. The docs' "permissioned" wording did not apply. | The page (`src/app/rpc.ts`) talks to the RPC directly from GitHub Pages; there is no proxy and no fallback if this changes. |
| 2 | `eth_getLogs` span | 10,000 blocks inclusive (`toBlock − fromBlock = 9,999`) answers; 10,001 → `-32012 requested range too large`. Five wide queries fired back-to-back → `-32005 rate limit exceeded` (observed once, not re-tested). The endpoint is load-balanced: a backend can answer `-32014 requested data not available` for a `toBlock` another backend just reported as head. | `src/lib/scan.ts`: ≤ 9,000-block windows, one request at a time 250 ms apart, 8 windows on open (4 from the head, 4 from the order's `createdBlock`), more only on request, never outside the order's life; `src/app/rpc.ts` retries `-32014` / `-32005` once. HTTP **429** was also seen on a sequential run of 8 `eth_getLogs` requests at 4/s (2026-09-18, one or two per page load, not every load); viem's transport retries those with back-off, so the page renders, but the console shows the refused request. |
| 3 | Explorer `/api` | Cloudflare "Just a moment…" challenge for a plain HTTPS client; the HTML pages render logged-out (HTTP 200). | Source verification through the API was not attempted from a script. The proof of what runs is the runtime-bytecode check in `scripts/preflight.py --bytecode` (on-chain code == `forge build` output with the immutable filled in). |
| 4 | `tx.gasprice` vs receipt `effectiveGasPrice` | The `Executed` event carries the price *after* `min(tx.gasprice, 2·basefee, maxGasPrice)`, so a receipt shows `tx.gasprice` only indirectly: on every 20 Gwei run (calibration ×3, `live`, `rejecting`, page run) both caps were above 20 Gwei and the event's price equalled the receipt's `effectiveGasPrice`, which is only possible if the contract's `tx.gasprice` was that same value. On the `capped` run (`effectiveGasPrice` 30 Gwei) the event shows the 20 Gwei cap, consistent with the cap binding. The one direct in-contract read (a probe contract that logged `tx.gasprice` itself, 2026-09-17) also matched to the wei. | `npm run recheck` asserts `price == min(effectiveGasPrice, 2·basefee, maxGasPrice)` on every committed row; a client change would show up there first. |
| 5 | Metering drift | Calibration contract (`OVERHEAD = 31,400`): receipt `gasUsed` 58,030 vs metered 56,927 on three runs — a constant 1,103 gas, spread 0. v1 (`OVERHEAD = 32,503`): drift 0, −6 (paused branch), 0, then 30/30 bench rows at 0. v2 (same constant; the once-per-transaction intrinsic credit lives inside the window): drift 0, −6, 0 and 30/30 at 0 again; a run costs 58,415 (+385 for the flag). | One immutable absorbs it. The paused branch over-meters by 6 gas (the `if (!paid)` jump taken and the `paid = 0` word), i.e. the executor is over-refunded by 120 Gwei ≈ $0.00000012 on a refused payment. Left as is; inside the ≤ 50-gas gate. |
| 6 | Base fee | `baseFeePerGas` exactly 20,000,000,000 on every block touched today; `eth_gasPrice` ≈ 20.19 Gwei. | `2 × basefee` = 40 Gwei cap never bound for honest executors; scripts and page send priority 0 with `maxFeePerGas = max(eth_gasPrice, 20 Gwei)`. |
| 7 | Decimals | `msg.value` and balances are 18-decimal; the explorer shows 6-decimal USDC. `0.02 USDC` is `20000000000000000` wei on the wire. | Every amount in the repo is native wei; the page shows both. Never the ERC-20 view for native movements. |
| 8 | Gas fee not logged | The receipt's two system-emitter `Transfer` logs are the payee leg and the executor leg; the fee itself is not a log. | "Real fee" on the page = `gasUsed × effectiveGasPrice` from the receipt, shown *beside* the contract's refund, never asserted by it. |
| 9 | Foundry ergonomics | `forge create ... --constructor-args 31400` must come **last** (it swallows following flags and then dials `localhost:8545`); `cast wallet decrypt-keystore` takes `--keystore-dir` + `CAST_UNSAFE_PASSWORD`, not `--password-file`. | `scripts/lib/env.ts` passes the password through the environment of a child process; nothing key-shaped is ever printed. |
| 10 | Block rate | Block 21,484,749 at 10:35:57 UTC and 21,485,807 at 10:44:54 UTC (2026-09-18, `cast block <n> --field timestamp` reproduces both): 1,058 blocks in 537 s → 1.97 blocks/s. | 9,000 blocks ≈ 76 min. A one-ended backward scan of 8 windows would only ever show the last ≈ 10 h, so the seeded order's day-one runs would vanish from "Recent runs" by the next day — which is why the scan reads from both ends of the order's life. |
| 11 | Costs at 20 Gwei | deploy 984,847 gas v1 / 1,008,235 v2 (≈ 0.02 USDC) · create 122–140k (0.0024–0.0028) · execute 58,030 v1 / 58,415 v2 (0.00117) · execute-with-refusal 60,565 · `NotDue` revert 24,323 · cancel 40,536 · Rejector deploy 55,209. | The `live` order's tip (0.01) is ≈ 8.6× the gas of a run. |
| 12 | Audit round 2 | A contract executor batching K `execute` calls in one transaction was credited the 21,000 intrinsic K times (v1). Found by the second independent audit, not by any test; fixed in v2 with a transient once-per-transaction flag and a test. | Redeploy 0.02 USDC; the whole mainnet proof (seed, page, bench, `NotDue`) was redone on v2 and v1's receipts kept. |
